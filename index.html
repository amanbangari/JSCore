Section 01

HTML gives it structure.
CSS gives it style.

Before writing a single line of JavaScript, understand the problem it solves — and why a static page simply can't cut it.

HTML + CSS Only

A Static, Frozen Webpage

HTML and CSS describe what things look like at load time. They cannot react to a user, remember anything, or change after the page has loaded. Your "like" button is just decoration.

What happens when clicked
Nothing. It's just a styled element.

A Living, Breathing Interface

JavaScript listens for events, stores state in memory, and updates the page — all in real time. This is what separates a webpage from a web application.

Listens · Updates state · Re-renders the UI

Section 02

The Original Problem:
Memory & Bytes

Your computer's memory is a massive grid of identical boxes — each holding exactly 8 bits. How do we store a name vs. an age in those same boxes?

The Core Insight

The boxes are identical.
The labels make them meaningful.

Memory doesn't know if address 0x0008 holds a username or a bank balance. Every bit is just a 1 or 0. It's up to the programming language — and your variables — to give them context.

Think of variables as labelled shelf slots:

"John"
26
null

Section 04

Data Types: What Goes in the Box

JavaScript's 5 primitive types — the fundamental building blocks of every value your program ever touches. Hover each card to explore.

String
Text data — any sequence of characters wrapped in quotes. Used for names, messages, and UI content.
"Hello, world!"
Number
All numbers — integers and decimals. JS uses a single type for both, stored as a 64-bit float.
42  ·  3.14  ·  -7
Boolean
Binary truth values. The backbone of all logic — if statements, loops, and conditions depend on these.
true  ·  false
Null
An intentional absence of value. You set this deliberately to say "there's nothing here on purpose."
null
Undefined
A variable that exists but hasn't been assigned a value yet. JS sets this automatically.
let x; // → undefined
Object
A collection of key-value pairs. Arrays and functions are also objects under the hood.
{ name: "Alex", age: 28 }

Section 05

Under the Hood:
How Numbers are Stored

Why does 0.1 + 0.2 not equal 0.3? The answer lies in how computers represent fractions in binary.

Key Insight

JavaScript has only one number type. Unlike other languages, there's no int vs float. Every number — 1, 3.14, 1e9 — uses this same 64-bit structure.

numbers.js
// All of these are the same type: "number" typeof 42 // "number" typeof 3.14 // "number" typeof Infinity // "number" typeof NaN // "number" ← Not-a-Number is a Number 🤯 // Safe integer range Number.MAX_SAFE_INTEGER // 9,007,199,254,740,991 Number.MIN_SAFE_INTEGER // -9,007,199,254,740,991
The Famous Floating Point Quirk
0.1 + 0.2 // → 0.30000000000000004 0.1 + 0.2 === 0.3 // → false ⚠️

The fraction 0.1 cannot be represented exactly in binary (just like ⅓ can't be expressed exactly in decimal). The 52-bit mantissa has to round — and that rounding error accumulates. Fix it by using toFixed() or multiply to integers before operating.

Operators are the actions that transform your data. Arithmetic, comparison, logical — they're how you make decisions and compute results.

Arithmetic
  • +Addition5 + 3 → 8
  • -Subtraction10 - 4 → 6
  • *Multiplication4 * 3 → 12
  • /Division9 / 3 → 3
  • %Modulo (remainder)7 % 2 → 1
  • **Exponentiation2 ** 8 → 256
Comparison
  • ==Loose equality"5" == 5 → true
  • ===Strict equality"5" === 5 → false

Section 07

Type Conversion:
The Hidden Trap

JavaScript quietly converts types when you're not looking. Understand explicit vs. implicit coercion — or face mysterious bugs.

Explicit You are in control
explicit.js
// You explicitly tell JS to convert Number("42") // 42 ✓ Number("3.14") // 3.14 ✓ Number("") // 0 ⚠️ Number(true) // 1 Number(false) // 0 String(42) // "42" Boolean(0) // false (falsy) parseInt("42px") // 42 ← great for CSS!
Real Use Case

A form's <input> always gives you a string. Before adding an age or price, you MUST convert it: Number(input.value).

Implicit JS does it silently
implicit.js
// JS converts for you — often surprisingly "5" + 1 // "51" ← string wins with + "5" - 1 // 4 ← - converts string to number "5" * 2 // 10 ← same for * and / true + 1 // 2 ← true becomes 1 false + 1 // 1 ← false becomes 0 null + 1 // 1 ← null becomes 0 "" == false // true ← both falsy (💀)
Classic Bug in Production

A developer reads a price from an input and does price + tax. Since price is a string, "99.99" + 8 = "99.998" — and the user is charged $99.998. 🔥

Section 08

Comparing Values:
=== vs ==

One checks value. The other checks value and type. The difference is the source of countless JavaScript bugs.

==
Loose Equality · Avoid in production

Coerces types before comparing. Two different things can appear "equal":

"5" == 5
0 == false
"" == false
null == undefined
Unpredictable — avoid in all production code
VS
===
Strict Equality · Industry standard

No type coercion. Different types are always unequal — predictable and safe:

"5" === 5
0 === false
"" === false
null === undefined
Predictable — always use this. ESLint enforces it.
rule-of-thumb.js
// ✅ Always use === in production if (userInput === "submit") { processForm(); } // ❌ Never use == — JS will surprise you if (userInput == "submit") { // This might match things you didn't expect }
